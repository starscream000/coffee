# v0.1.0 plan (Milestone 1)

> Status: **Draft for the owner's go-ahead** (2026-10-09). Nothing in this plan
> starts until the owner approves it. Check IDs (A, S, F, I) refer to the
> [definition of done](v0.1.0-definition-of-done.md).

## How the work is cut

- One branch per row below, in this order; each later branch starts from
  `main` after the earlier ones are merged.
- Each branch is small enough to review in one sitting: one module or one group
  of related actions, its unit tests, its docs and its `CHANGELOG.md` entry.
- Each branch keeps every check that is already green, green.
- From branch 7 on, CI runs the integration tests in Chromium on Linux, Windows
  and macOS, so every check below is proven on all three systems when it turns
  green, not only at the end.
- Dependencies are added only in the branch that first needs them (named in the
  table). Playwright is pinned to an exact version.

## Risks and how the plan handles them

- **Branch 8 is the largest.** If its review takes more than one sitting, it is
  split before review into `feat/runner-core` (lifecycle, events, run folder)
  and `feat/runner-rows-skip` (data rows, `skip`, `keepRuns`), with the checks
  divided accordingly.
- **The trace viewer is internal to Playwright** (ADR 0007). Branch 13's I5
  check is the guard; a Playwright upgrade that breaks it fails CI.
- **Windows path lengths** (ADR 0015): the integration job runs on Windows from
  branch 7 on, so long run-folder paths show up early.
- **Names**: the command, data folder and npm scope are still interim. Renaming
  before branch 1 is cheapest; after branch 14 it also touches the CLI's
  printed output and the acceptance checks.
