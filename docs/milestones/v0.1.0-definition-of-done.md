# v0.1.0 definition of done

> Status: **Draft for owner approval** (2026-10-09). The command name `coffee`,
> the `.coffee/` folder and the `@test-tool` scope are interim names
> ([ADR 0019](../adr/0019-four-product-names.md)).

v0.1.0 is done when **every check below passes on Windows, macOS and Linux in
CI** (the `verify` and `acceptance` jobs of `.github/workflows/ci.yml`, Node
from `.nvmrc`), and the release checklist at the end is complete. Every check
has an ID (A = acceptance command, S = sample that must pass, F = fixture that
must fail in a specified way, I = integration test) so that
[the plan](v0.1.0-plan.md) can say which branch turns which check green.

## Scope recap

Step file parser and validator, action registry with all built-in actions,
context and variables, runner, event stream over the protocol, and a CLI that
runs step files against the demo app and prints results. Chromium only.

## Commands

Run from the repository root on each of the three systems:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install --with-deps chromium   # browser download; --with-deps matters on Linux
pnpm verify             # type check, lint, format check, unit tests
pnpm test:integration   # engine and protocol tests against the demo app in Chromium (I checks, S and F samples)
pnpm acceptance         # the CLI commands below, as a script that checks exit codes and output (A checks)
```

`pnpm acceptance` starts the demo app on port 4310, then runs these commands
and checks each exit code and the listed output. They can also be run by hand
(`pnpm cli` runs the built CLI; the script name avoids the product name):

The CLI's exit codes: 0 no test failed, 1 at least one test failed, 2 invalid
step files, config or arguments, 3 engine could not be started or refused the
CLI.

## Sample step files

Node web server with no framework, started by the test harness). Together they
use **every built-in action** at least once. A2 runs everything under `tests/`;
files under `fixtures/` are excluded by the config's `tests` glob and run only
when named.

## Integration tests (`pnpm test:integration`)

Besides running the samples in-process, these tests spawn the engine as a
client would:

| ID  | Check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| I1  | **Handshake**: compatible `initialize` succeeds; any request before it gets `NotInitialized`; an incompatible version gets `IncompatibleProtocol` and the process exits with code 3.                                                                                                                                                                                                                                                                                                                               |
| I2  | **Events**: for S5, the event sequence (types, `seq`, `testId`, `stepId`, `section`) matches a checked-in expectation; every `stepStarted.params` is the canonical long form.                                                                                                                                                                                                                                                                                                                                      |
| I3  | **Message size**: a 5 MiB line from the client gets `MessageTooLarge` with `id: null` and the session keeps working; an assertion whose `actual` is a 10 MB string produces a `stepFailed` under 4 MiB with the value truncated and marked.                                                                                                                                                                                                                                                                        |
| I4  | **Cancellation**: `cancelRun` during a 30-second `wait.element` ends the step within 2 seconds with `Cancelled`; `after` steps run; `testFinished` has status `cancelled`.                                                                                                                                                                                                                                                                                                                                         |
| I5  | **Page states**: with `snapshots: always`, each step produces `screenshotReady` (PNG exists), `snapshotReady` and `snapshot.state: "saved"`; `openSnapshot` opens the snapshot in the viewer without error.                                                                                                                                                                                                                                                                                                        |
| I6  | **Snapshot settings**: with `onFailure`, passing steps report `snapshot.state: "skipped"` and leave no chunk, a failing step keeps its chunk; with `off`, tracing is never started and every step reports `"skipped"`.                                                                                                                                                                                                                                                                                             |
| I7  | **Snapshot failure never fails a test**: with masking forced to fail (test hook), the step still passes, reports `snapshot.state: "failed"` with a reason, keeps its screenshot and leaves no chunk; `openSnapshot` with the viewer files missing returns `SnapshotUnavailable` with `data.screenshot`.                                                                                                                                                                                                            |
| I8  | **Run folder**: the layout of [ADR 0015](../adr/0015-results-layout.md); `events.ndjson` equals the events received over the protocol; no event carries file contents.                                                                                                                                                                                                                                                                                                                                             |
| I9  | **keepRuns**: with `keepRuns: 3`, after 5 runs exactly the 3 newest run folders remain; a non-run folder in `runs/` is untouched; with `keepRuns: 0` nothing is deleted.                                                                                                                                                                                                                                                                                                                                           |
| I10 | **Schemas**: every message sent in these tests validates against the JSON Schemas in `packages/protocol/schema/`.                                                                                                                                                                                                                                                                                                                                                                                                  |
| I11 | **Saved logins**: a second run within `maxAge` reuses the saved state (the login flow does not run); after `maxAge` (set to 1s in the test config) it runs again; the cache file names are hashes and no file under `.coffee/logins/` contains a login parameter value. At the start of a run, a state older than its `maxAge` and a state whose metadata names a removed login or environment are both deleted; a state file held open (test hook) gives a `LoginCleanupFailed` warning and the run still passes. |
| I12 | **One SDK copy**: a user action in a repository that has a different SDK version installed still gets the engine's `defineAction`, `target()` and errors (checked by the `sdkError` tag), and `openProject` reports `SdkVersionMismatch` with both versions.                                                                                                                                                                                                                                                       |
| I13 | **stdout hygiene**: a user action calling `console.log` does not corrupt the protocol stream.                                                                                                                                                                                                                                                                                                                                                                                                                      |

## Release checklist

- [ ] All of the above green on Windows, macOS and Linux in CI for the release
      commit. **The tag is not created until CI has passed on all three
      systems.**
- [ ] No skipped or `.only` tests (`vitest` fails the run if any exist).
- [ ] Every ADR that v0.1.0 relies on is Accepted; docs match the implementation
      (status lines no longer say "Proposal" or "Draft").
- [ ] `PROTOCOL_VERSION` is `0.1.0`; JSON Schemas generated and committed.
- [ ] All packages at version `0.1.0`; `CHANGELOG.md` has a `[0.1.0]` section
      with the date.
- [ ] The release pull request is merged into `main` as a merge commit by the
      reviewer; the annotated tag `v0.1.0` is put on that merge commit
      (`git tag -a v0.1.0 -m "v0.1.0"`) only after CI has passed on it.
